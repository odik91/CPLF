# Capability Framework CPLF

**Version:** 0.1 (Frozen)  
**Peran:** Jembatan antara filosofi dan silabus  
**Konteks:** MA — Multimedia (pemrograman web)

## Mengapa Capability dulu?

Silabus tanpa capability mudah berubah menjadi daftar bab (“HTML minggu 3”).  
Capability menjawab: **kemampuan apa yang tumbuh di akhir kelas?** Materi dan tool hanya media untuk capability itu.

Kontrak guru–siswa di akhir tahun: bukan “berapa bab selesai”, melainkan “capability mana yang sudah tumbuh”.

---

## Profil Lulusan CPLF-MA

Lulusan membawa identitas:

> Saya mampu belajar hal baru dan menyelesaikan masalah secara bertanggung jawab — dengan atau tanpa AI.

Bukan cetakan wajib “web developer” atau “AI engineer”.  
Mereka boleh menjadi apa pun; yang dibawa adalah cara bernalar, membangun, dan mempertanggungjawabkan solusi.

### Dimensi profil

| Dimensi | Deskripsi singkat |
|---------|-------------------|
| Bernalar | Klarifikasi, bukti, alasan, konteks |
| Membangun | Dari masalah → artefak yang bisa diuji |
| Berkomunikasi | Menjelaskan mengapa, bukan hanya apa |
| Berkolaborasi | Kerja tim, umpan balik, Git dasar (XI+) |
| Bertanggung jawab | Etika, privasi, dampak solusi (terutama XII) |

## Capability per Kelas

Bahasa capability **menghindari** “menguasai HTML/JS”. Tool disebut hanya sebagai contoh media.

### Akhir Kelas X (Fase E)

**Pernyataan induk:**  
Mampu mengubah masalah sederhana menjadi solusi web sederhana dan menjelaskan alasan di balik solusi tersebut.

| Kode | Domain | Capability |
|------|--------|------------|
| CX-B1 | Berpikir | Mengidentifikasi masalah dan membatasi lingkupnya |
| CX-B2 | Berpikir | Memecah masalah menjadi langkah-langkah kecil yang berurutan |
| CX-B3 | Berpikir | Mengevaluasi dua solusi sederhana dan memilih dengan alasan |
| CX-B4 | Bernalar | Mengklarifikasi klaim (teman/AI/internet) sebelum dipakai |
| CX-T1 | Teknis | Merepresentasikan informasi secara visual di halaman web |
| CX-T2 | Teknis | Menerjemahkan logika menjadi instruksi yang dapat dieksekusi |
| CX-T3 | Teknis | Memakai kondisi, pengulangan, dan fungsi sederhana secara tepat-guna |
| CX-T4 | Teknis | Melakukan debugging sederhana berdasar observasi error |
| CX-K1 | Komunikasi | Menjelaskan alasan pemilihan solusi kepada teman/guru |
| CX-K2 | Komunikasi | Menerima umpan balik dan memperbaiki artefak |
| CX-C1 | Karakter | Berani mencoba dan tidak takut salah dalam proses belajar |

**Contoh artefak:** halaman profil/kegiatan; kalkulator sederhana (mis. zakat); to-do/absensi mini; algoritma + flowchart + implementasi JS kecil.

### Akhir Kelas XI (Fase F — tahap bangun)

**Pernyataan induk:**  
Mampu merancang dan membangun aplikasi web yang terdiri dari beberapa komponen serta bekerja secara kolaboratif.

| Kode | Domain | Capability |
|------|--------|------------|
| CXI-B1 | Berpikir | Memodelkan alur aplikasi (input–proses–output–state) |
| CXI-B2 | Berpikir | Memilih struktur data sederhana sesuai kebutuhan masalah |
| CXI-T1 | Teknis | Membangun interaksi pengguna (DOM, event) yang konsisten |
| CXI-T2 | Teknis | Menggunakan proses asynchronous untuk mengambil/mengolah data |
| CXI-T3 | Teknis | Mengorganisasi kode menjadi bagian yang bisa dipakai ulang |
| CXI-T4 | Teknis | Menyimpan dan memulihkan data (lokal / JSON / konsep basis data) |
| CXI-T5 | Teknis | Memakai kontrol versi dasar untuk kerja tim |
| CXI-K1 | Komunikasi | Menyusun requirement singkat yang dapat diuji |
| CXI-K2 | Kolaborasi | Membagi tugas, mereview, dan mengintegrasikan kontribusi |
| CXI-C1 | Karakter | Merawat kualitas kode (keterbacaan, perbaikan bertahap) |

**Contoh artefak:** absensi kelas; katalog perpustakaan mini; dashboard data sederhana; aplikasi yang memakai fetch/API publik.

### Akhir Kelas XII (Fase F — tahap nilai)

**Pernyataan induk:**  
Mampu memilih dan mengintegrasikan teknologi yang tepat untuk masalah nyata, termasuk memanfaatkan AI secara bertanggung jawab.

| Kode | Domain | Capability |
|------|--------|------------|
| CXII-B1 | Berpikir | Memilih pendekatan (aturan / data / model) sesuai masalah |
| CXII-B2 | Berpikir | Menjelaskan batasan model/prediksi dan risiko salah |
| CXII-T1 | Teknis | Menyiapkan dan mentransformasi data untuk keperluan prediksi |
| CXII-T2 | Teknis | Memakai pipeline dasar model di browser (load/train/predict) |
| CXII-T3 | Teknis | Mengintegrasikan model/hasil AI ke antarmuka web |
| CXII-T4 | Teknis | Menerapkan transfer learning / model siap pakai secara kritis |
| CXII-K1 | Komunikasi | Mempresentasikan solusi + alasan teknis + dampak |
| CXII-C1 | Etika | Menilai konsekuensi (privasi, bias, ketergantungan pada AI) |
| CXII-C2 | Karakter | Memosisikan AI sebagai partner berpikir, bukan pengganti |

**Contoh artefak:** deteksi gesture/ekspresi; klasifikasi gambar sederhana; asisten web sekolah; project nilai komunitas (bonus: AI agent / “Jarvis” ringan).

## Dari Capability ke Learning Outcome ke Pertemuan

```text
Capability
    ↓
Learning Outcome (terukur di unit/semester)
    ↓
Pertemuan (Experience → … → Transfer)
```

Contoh:

- **Capability:** CX-B2 memecah masalah  
- **LO:** Siswa menyusun algoritma masalah sehari-hari dalam flowchart dan pseudocode  
- **Pertemuan:** Experience robot mie → Cognitive Trap bungkus mi → konsep instruksi eksplisit

## Asesmen Capability (filosofi)

Jangan hanya cek “kode jalan”. Bukti capability mencakup:

| Aspek | Yang diamati |
|-------|----------------|
| Observation | Ketelitian melihat gejala / output |
| Reasoning | Kualitas alasan & klarifikasi |
| Communication | Kejelasan penjelasan |
| Iteration | Perbaikan setelah umpan balik |
| Transfer | Membawa pola ke masalah baru |
| Technical Skill | Ketepatan penggunaan media/tool |

Rubrik detail: [09-rubrik](../09-rubrik/09_Rubrik_Index.md).

## Anti-Pattern

- Menulis silabus sebagai daftar tag HTML/CSS tanpa capability.
- Menyatakan “tuntas JS” tanpa bukti CX/CXI.
- Menguji hafalan istilah ML tanpa CXII-B2 (batasan & risiko).
