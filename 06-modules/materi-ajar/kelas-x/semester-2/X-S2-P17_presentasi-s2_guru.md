## 1. Pengetahuan yang Dikuasai Guru

- **Prinsip presentasi S2:** **reasoning > demo cantik** — rubrik penekanan COM/REA/TEC.
- **Format:** 3–4 menit per siswa/kelompok — adjust jumlah presenter vs 90 menit (±8–10 @ 4 menit).
- **Struktur 4 menit:**

| Menit | Isi |
|-------|-----|
| 0–1 | Masalah & user (siapa pakai halaman ini) |
| 1–3 | Demo fitur DoD — live di browser |
| 3–4 | **Mengapa** layout/validasi/struktur + 1 kesulitan & perbaikan |

- **Pool pertanyaan guru** (dari modul):
  - Mengapa layout/struktur HTML demikian?
  - Validasi apa yang kamu lindungi?
  - Jika user X, apa yang bisa gagal?
  - AI dipakai? Bagian mana + klarifikasi?
- **Q&A bernalar (60–75 menit):** guru minta "mengapa?" — bukan "wow".
- **Skor draft 6 aspek** — untuk guru, tidak dibacakan ranking di depan kelas.
- **Preview P18:** kumpulkan artefak untuk portofolio tahun X.
- **Dokumentasi:** foto/video arsip MA — izin siswa.

## 3. Etika Penyampaian Pertemuan Ini

| Aturan | Penerapan spesifik hari ini |
|--------|----------------------------|
| **Presentation coaching** | Guru bantu struktur, confidence, timing — **bukan** polish kode menit terakhir. |
| **Jangan takeover demo** | Siswa yang klik/jalankan browser — guru timekeeper & moderasi Q&A. |
| **Jangan perbaiki project di depan kelas** | Feedback process untuk P18/portofolio, bukan live fix showcase. |
| **Rayakan proses** | Puji reasoning, iterasi peer, kejujuran tentang kesulitan — bukan "paling cantik". |
| Ranking | **Dilarang** — tidak ada juara 1/2/3 toxic |
| Q&A | Model pertanyaan bernalar — "Mengapa validasi di JS?" bukan "Kok jelek" |

### Presentation coaching — peran guru

Guru adalah **coach**, bukan co-author:

- **Sebelum kelas / 5 menit pertama:** spot-check outline 4 bagian + happy path demo.
- **Saat demo:** timer visible; isyarat 1 menit tersisa.
- **Setelah demo:** 1–2 pertanyaan "mengapa?" — guru moderasi jika menyerang personal.
- **Whisper coaching** (jika panik): "Mulai dari masalah — napas — buka browser — happy path."

### Larangan menit terakhir

```text
"Sini laptopnya bu, pak/bu betulkan CSS/JS dulu biar demo lancar"
→ Tolak — merusak bukti REA/ITR; demo apa adanya + jelaskan blocker (OBS)
```

### Script coaching reasoning

```text
"Menit mengapa lebih penting dari animasi cantik."
"Jika demo error — sebut gejala, hipotesis. Itu OBS — bukan malu."
"Tanya peer: keputusan desain, bukan 'kenapa warna jelek'."
"AI dipakai? Sebut bagian + bukti klarifikasi per baris/selector."
```

## 4. Materi Inti

### Rubrik presentasi (0–5 menit)

Jelaskan ke siswa — **bukan** angka:

- Dinilai: clarity masalah, demo DoD, **reasoning** desain, iterasi, respons Q&A
- Rubrik lengkap: [09_Rubrik_Project](../../../09-rubrik/09_Rubrik_Project.md) — guru saja

### Presentasi bergiliran (5–60 menit)

**Checklist presenter** (coaching sebelum/antar demo):

- [ ] Bisa jawab masalah + user tanpa baca slide penuh
- [ ] Demo **happy path** live + 1 edge case jika sempat
- [ ] Siap tunjuk bukti revisi peer (ITR) — before/after singkat
- [ ] Backup: screenshot jika live demo gagal — jelaskan gejala
- [ ] Siap jawab pool pertanyaan guru (layout, validasi, AI)

### Q&A bernalar (60–75 menit)

Guru & peer — contoh pertanyaan **web S2**:

| PRJ | Pertanyaan bernalar |
|-----|---------------------|
| PRJ-01 | "Mengapa pesan error di DOM bukan alert?" |
| PRJ-02 | "Bagaimana list kosong ditampilkan ke user?" |
| PRJ-03 | "Data absensi disimpan di mana — apa risikonya?" |
| PRJ-04 | "Mengapa struktur section/nav demikian untuk audience ekskul?" |

**Universal:**

- "Validasi apa yang melindungi user dari input salah?"
- "Jika layar HP sempit, apa yang bisa gagal?"
- "Bagian mana AI bantu — selector/CSS mana yang kamu jelaskan sendiri?"

### Skor draft + catatan (75–85 menit)

Guru isi rubrik 6 aspek — narasi untuk laporan, bukan diumumkan ranking.

### Preview P18 (85–90 menit)

Ingatkan: kumpulkan link/screenshot S1+S2 + refleksi — portofolio tahun X.

## 5. Alur Live Coding / Live Modeling

### Persiapan

- Urutan presenter + timer (HP/proyektor).
- Rubrik project — guru only.
- Kamera/foto izin — arsip MA.
- Browser siswa siap — **tidak** sesi last-minute coding.
- Pool pertanyaan guru di papan.

### Skrip showcase

```text
[0–5] Aturan: reasoning > cantik; 3–4 menit; Q&A mengapa; no ranking
[5–60] Presentasi bergiliran
       Guru: timekeeper, model applause proses, moderasi Q&A
       Coaching whisper jika perlu — bukan fix kode
[60–75] Q&A bernalar — guru pilih 2–3 pertanyaan dari pool
[75–85] Skor draft rubrik (guru) + catatan narasi
[85–90] Preview P18 portofolio — artefak apa dikumpulkan
```

### Jika demo gagal live

1. Siswa sebut gejala (OBS) — console, layout, network
2. Tunjuk screenshot backup atau jelaskan langkah yang diharapkan
3. Guru normalisasi — "Iterasi & honesty = ITR/COM"
4. Lanjut Q&A reasoning — desain tetap bisa dinilai

### Modeling pertanyaan Q&A (papan)

```text
✓ "Mengapa AND dua kondisi zakat, bukan OR?"
✓ "Selector #id vs .class — mengapa pilih id di tombol submit?"
✗ "Kok warnanya norak?" (redirect ke kontras/readability)
```

---

## 6. Latihan Membaca Kode

Presentasi **bukan** walkthrough kode baris-per-baris. Gunakan snippet untuk **latihan Q&A reasoning** (opsional 5 menit sebelum demo pertama):

```html
<section id="hasil">
  <p id="nominal-out"></p>
</section>
```

```javascript
document.getElementById("btn").addEventListener("click", () => {
  const v = document.getElementById("input").value;
  document.getElementById("nominal-out").textContent = v * 0.025;
});
```

| Pertanyaan coaching (Q&A) | Kunci |
|---------------------------|-------|
| Validasi apa yang missing? | Empty, non-number, negatif |
| Mengapa output di `<section>` terpisah? | Semantik + layout — hasil jelas |
| Tanya peer bernalar? | "Mengapa listener di click bukan submit form?" |

---

## 7. Praktik Mandiri Siswa

1. **Presentasi 3–4 menit** — demo live + reasoning.
2. **Jawab Q&A** — minimal 1 pertanyaan "mengapa?".
3. **Tunjuk bukti iterasi** — peer revisi singkat.
4. **1 pertanyaan bernalar** ke presenter lain.
5. **Kumpulkan artefak** — link/screenshot untuk P18.
6. **Refleksi singkat** — 1 kalimat: keputusan desain terpenting.

---

## 8. Kesalahan Umum

| Siswa | Guru |
|-------|------|
| Demo = baca slide kode penuh | Coaching: browser live, slide minimal |
| Takut error live | Normalisasi OBS — backup screenshot |
| Peer roast desain | Moderasi — redirect ke UX & DoD |
| Guru over-praise hanya yang cantik | Puji reasoning & iterasi semua presenter |
| Ranking kelas | Explicit: tidak ada juara |
| Menit terakhir minta guru fix | Tolak — demo apa adanya |
| Skip menjelaskan AI usage | Tanya dari pool — klarifikasi wajib |
