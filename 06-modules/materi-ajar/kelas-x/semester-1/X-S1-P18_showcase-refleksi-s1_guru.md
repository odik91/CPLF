## 1. Pengetahuan yang Dikuasai Guru

- **Format showcase:** 3 menit demo + 1 menit **mengapa** (reasoning) per siswa/kelompok.
- **Kapasitas waktu:** ±8–10 presenter @ 4 menit — adjust urutan/slide gatekeeper.
- **3 pertanyaan wajib presenter:**
  1. Masalah apa?
  2. Mengapa solusi ini (bukan solusi lain)?
  3. Satu kesalahan & perbaikan?
- **Peer:** 1 pertanyaan bernalar per demo — bukan roast.
- **Guru closing (70–80 menit):** pola kuat semester + area perbaikan S2 — tanpa ranking toxic.
- **Refleksi tertulis (80–90 menit):** 3 capability CX yang tumbuh + 1 target S2.
- **Penilaian:** skor project 6 aspek + narasi — lihat rubrik project.
- **Dokumentasi:** foto/portofolio untuk S2 — rayakan proses.

## 2. Recall Spiral

|------------|------------------------------|
| Dari P01 sampai P18 — satu perubahan cara berpikir? | (siswa personal — error=info, spec dulu, dll.) |
| Capability CX apa yang paling terasa di project? | OBS/REA/ITR/COM — bahasa siswa |
| Satu hal S2 ingin lebih kuat? | Target refleksi |

---

## 3. Etika Penyampaian Pertemuan Ini

| Aturan | Penerapan spesifik hari ini |
|--------|----------------------------|
| **Coaching presentasi** | Guru bantu struktur & confidence — bukan polish kode menit terakhir. |
| **Jangan takeover demo** | Siswa yang klik/jalankan — guru hanya timekeeper & facilitator Q&A. |
| **Jangan perbaiki project di depan kelas** | Feedback process untuk S2, bukan live fix showcase. |
| **Rayakan proses** | Puji reasoning, iterasi, kejujuran tentang kesalahan — bukan "paling cantik". |
| Ranking | **Dilarang** — tidak ada juara 1/2/3 toxic |
| Peer Q&A | Model pertanyaan bernalar — "Mengapa pilih loop bukan ulang manual?" |

### Presentation coaching — peran guru

Guru adalah **coach**, bukan co-author:

- Sebelum kelas: 2 menit/siswa — cek outline 3 pertanyaan wajib.
- Saat demo: timer visible; isyarat 1 menit tersisa.
- Setelah demo: 1 peer question — guru moderasi jika menyerang personal.

**Larangan menit terakhir:** "Sini laptopnya bu, pak/bu betulkan dulu biar demo lancar" — merusak bukti REA/ITR.

---

## 4. Materi Inti

### Struktur presentasi 4 menit

| Menit | Isi |
|-------|-----|
| 0–1 | Masalah & konteks (siapa user, apa pain) |
| 1–3 | Demo fitur DoD — live, bukan video panjang |
| 3–4 | **Mengapa** solusi ini + 1 kesalahan & perbaikan |

### Coaching sebelum showcase (prep P17 atau 5 menit pertama P18)

**Checklist presenter:**

- [ ] Bisa jawab 3 pertanyaan wajib tanpa baca slide penuh
- [ ] Demo path **happy path** + 1 edge case jika sempat
- [ ] Siap tunjuk bukti revisi peer (ITR)
- [ ] Backup: screenshot jika live demo gagal — jelaskan gejala (OBS)

### Pertanyaan peer bernalar (contoh)

- "Langkah mana yang paling sering ROBI salah paham?" (PRJ-01)
- "Apa yang terjadi di antrian ke-11?" (PRJ-02)
- "Bagaimana kamu uji input invalid?" (PRJ-03)

### Guru synthesis (70–80 menit)

2–3 pola **kuat** + 2 area **umum perlu perbaikan S2** — contoh:

- Kuat: semakin banyak yang baca error dulu
- Perbaikan S2: validasi input, struktur file, dokumentasi

### Refleksi capability

Draft Progress Card — 3 CX capability + bukti dari semester (bukan nilai angka di kelas).

---

## 5. Alur Live Coding / Live Modeling

### Persiapan

- Urutan presenter + timer (HP/proyektor).
- Rubrik project — untuk guru, tidak dibacakan angka di depan kelas.
- Kamera/foto izin — dokumentasi portofolio.
- **Tidak** sesi last-minute coding.

### Skrip showcase

```text
[0–5] Aturan: 3 menit demo + 1 menit mengapa; 1 peer question; applause proses
[5–55] Presentasi bergiliran
       Guru: timekeeper, model applause, moderasi Q&A
       Coaching whisper (jika panik): "Mulai dari masalah — napas — demo happy path"
[55–70] Peer: ringkasan 1 insight per demo (opsional sticky note)
[70–80] Guru synthesis — pola kuat & target S2
[80–90] Refleksi tertulis individual + kumpul Progress Card draft
```

### Script coaching (sebelum / antar demo)

```text
"Jika demo error — itu OK. Sebut gejala, jelaskan hipotesis. Itu OBS."
"Menit mengapa lebih penting dari animasi cantik."
"Peer question: tanya keputusan, bukan 'kenapa jelek'."
```

### Jika demo gagal live

1. Siswa sebut gejala (OBS)
2. Tunjuk screenshot backup atau jelaskan langkah
3. Guru normalisasi — "Iterasi lanjut S2"

---

## 6. Latihan Membaca Kode

Showcase **bukan** membaca kode baris-per-baris. Gunakan snippet hanya untuk **latihan peer question** sebelum demo (opsional 5 menit):

```javascript
// Cuplikan anonim — teman latih tanya "mengapa"
if (harta >= nisab && haul >= 1) {
  console.log("Wajib zakat");
}
```

| Pertanyaan peer (coaching) | Kunci |
|----------------------------|-------|
| Tanya bernalar? | "Mengapa AND, bukan OR?" / "Bagaimana nisab didefinisikan?" |
| Bukan | "Salah syntax" di showcase |

---

## 7. Praktik Mandiri Siswa

1. **Presentasi 4 menit** — demo + mengapa.
2. **Jawab 3 pertanyaan wajib** — lisan.
3. **1 peer question** — untuk presenter lain.
4. **Refleksi tertulis** — 3 capability + 1 target S2.
5. **Progress Card draft** — kumpul ke guru.

---

## 8. Kesalahan Umum

| Siswa | Guru |
|-------|------|
| Demo = baca slide kode penuh | Coaching: demo live, slide minimal |
| Takut error live | Normalisasi OBS — rencana backup |
| Peer roast | Moderasi — redirect ke keputusan design |
| Guru over-praise hanya yang cantik | Puji reasoning & iterasi semua presenter |
| Ranking kelas | Explicit: tidak ada juara |
| Menit terakhir minta guru fix | Tolak — demo apa adanya + jelaskan blocker |
