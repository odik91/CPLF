## Cognitive Trap

Review = opini selera; atau gagal = buang semua / generate ulang.

## Guiding Questions

1. AC gagal + bukti?  
2. Perbaikan #1?  
3. Setelah revisi: ✅ atau ❌?

## Exit Ticket

1. AC yang diperbaiki + status  
2. Selera vs kriteria penerimaan  
3. Yang stabil untuk dibawa ke P13  

## Formatif

**Menganalisis · C4** · **Mengevaluasi · C5** · Observasi bukti · Penalaran prioritas.

## Catatan Guru

Artefak wajib buka. Feedback = temuan+bukti. Rayakan penutup Blok 2. Preview P13 singkat.

## B. Materi pendukung (lengkap)

> **RAHASIA GURU**

### 1. Pengetahuan ringkas

Checkpoint Blok 2 — bukan tag baru.  
AC terukur. Revisi terarah. Larang hakim “keren.”

### 2. Recall

P04 spek/AC · P07–P11 artefak · hari ini uji + perbaiki.

### 3. Etika

Feedback hormat. No kunci “halaman sempurna.” Tolak generate ulang sebagai pelarian.

### 4. Skrip live (180')

```text
[0 — Orientation 0–10]
"Blok 2 hampir tutup: semantik, CSS, napas layout, peta section, form jujur.
Hari ini bukan fitur baru. Hari ini: janji spek — ditepati atau belum?"
Recall P04: 1 siswa sebut contoh AC yang BUKAN 'keren'.

[1 — Scaffold 10–30]
Proyeksi artefak sampel (boleh punya guru / anonymized).
Jalankan 5–6 item checklist keras: ada yang ❌.
We do: "Ini gagal karena selera atau karena AC?"

[2 — Experience 30–50]
3 kartu temuan:
1. nav href=#kontak tapi id=contact
2. "Warna kurang aesthetic"
3. input tanpa name
Klasifikasi: AC nyata vs opini. Buang yang opini dari antrean perbaikan.

[3 — Trap 50–65]
A: Peer hanya bilang "kurang keren, ganti tema."
B: Siswa dapat 1 ❌ lalu hapus semua file + minta AI generate ulang.
C: Review tanpa membaca spek pemilik.
Debat: obat = checklist + bukti + revisi item gagal + uji ulang.

[4 — Clarify + Concept 65–85]
Siklus di papan:
SPEK/AC → UJI → TEMUAN (bukti) → PRIORITAS → PERBAIKI → UJI ULANG
Checklist Blok 2: A spek · B semantik · C CSS · D nav · E form

[5 — Practice mini 85–95]
Siswa tulis/tempel spek-AC singkat (3–5 checkbox) untuk halamannya.
Jika hilang: pulihkan dari yang sudah pernah ditulis P04–P11.

[6–7 — Scaffold + Practice 105–165]
I do: isi 1 baris lembar peer dengan bukti ("klik Layanan → tidak loncat; href=#layanan id=Layanan").
You do:
  Putaran 1 (≈20'): peer isi lembar
  Putaran 2 (≈25'): pemilik perbaiki prioritas 1–2 item
  Putaran 3 (≈15'): uji ulang + centang ulang
Tolak: menambah animasi/JS sebagai pelarian; debat selera panjang.

[8 — Exit 165–180]
"Blok 2: halaman static yang bisa dijelaskan vs spek."
Preview P13: JS — halaman mulai bereaksi (bukan ganti fondasi static).
Exit ticket.
```

### Lembar peer (model — boleh diprint)

```text
Pemilik: __________  Reviewer: __________
Spek/AC terbaca? [ ] ya  [ ] belum → minta pemilik tulis dulu

Item | ✅/❌ | Bukti singkat
-----|------|----------------
Semantik landmark | | 
Hierarki judul | | 
CSS + keterbacaan | | 
Nav loncatan | | 
Form label/name | | 
Kejujuran klaim | | 

Prioritas perbaikan #1: …
Prioritas #2: …

Setelah revisi (pemilik):
AC #1 sekarang: ✅/❌  catatan: …
```

### 5. Kesalahan umum

| Siswa | Guru |
|-------|------|
| Feedback “kurang aesthetic” | Meladeni debat selera |
| Rewrite total | Memuji “semangat” tanpa cek AC |
| Peer tidak klik nav/form | Review hanya lihat sekilas |
| Spek hilang | Tetap memaksa review |
| Sembunyi di fitur baru | Tidak tarik kembali ke checklist |

### 6. Checklist exit guru

- [ ] Demo sampel vs checklist  
- [ ] Trap selera / rewrite  
- [ ] Peer + revisi + uji ulang  
- [ ] Penutup Blok 2  
- [ ] Preview P13  
- [ ] Pendukung tidak ke siswa  

### 7. KBC

**Panca cinta:** Ilmu · kejujuran · tanggung jawab pada karya  
**Kait:** Menerima temuan berdasar spek = jujur pada janji tertulis.
