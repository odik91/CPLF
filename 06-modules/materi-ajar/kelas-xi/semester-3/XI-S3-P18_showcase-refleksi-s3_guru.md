## 1. Pengetahuan yang Dikuasai Guru

- **Transformasi hari ini:** dari project selesai → **bukti capability** + refleksi growth.
- **Format presentasi wajib (modul):**
  - DoD / acceptance final
  - 1 slide reasoning (boleh kertas)
  - Sebelum–sesudah 1 revisi
  - Transfer: pola dipakai di mana lagi
- **Timeline:** showcase 4–5 menit → peer 2 pertanyaan + 1 apresiasi → jurnal refleksi X→XI S3 → closing preview S4.
- **Struktur 4–5 menit:**

| Menit | Isi |
|-------|-----|
| 0–1 | Masalah & user |
| 1–2 | IPO + blueprint singkat |
| 2–4 | Demo DoD — live browser |
| 4–5 | Iterasi (before/after) + transfer S4 |

- **Rubrik:** [09_Rubrik_Project](../../../09-rubrik/09_Rubrik_Project.md) — REA, ITR, COM, TEC — guru isi, **bukan** ranking di depan kelas.
- **Peer Q&A:** 2 pertanyaan bernalar + 1 apresiasi spesifik — bukan roast.
- **Jurnal refleksi:** dari Kelas X ke XI S3 — **3 perubahan cara berpikir** (bukan daftar fitur).
- **Undang wali/OSIS opsional** — simpan link artefak untuk portofolio S4 P18 (modul).

## 3. Etika Penyampaian Pertemuan Ini

| Aturan | Penerapan spesifik hari ini |
|--------|----------------------------|
| **Presentation coaching** | Guru bantu struktur, timing, confidence — **bukan** polish kode menit terakhir. |
| **Jangan takeover demo** | Presenter klik browser — guru timekeeper & moderasi Q&A. |
| **Jangan perbaiki project di depan kelas** | Feedback untuk growth — bukan live fix showcase. |
| **Rayakan proses** | Puji reasoning, iterasi peer, kejujuran kesulitan — bukan "paling cantik". |
| Ranking | **Dilarang** — tidak ada juara 1/2/3 toxic |
| Q&A | Model pertanyaan bernalar — "Mengapa state shape demikian?" bukan "Kok jelek" |
| Refleksi | Guru **tidak** menulis jurnal siswa |

### Presentation coaching — peran guru

- **Sebelum showcase:** spot-check outline 5 bagian + happy path + bukti revisi.
- **Saat demo:** timer visible; isyarat 1 menit tersisa.
- **Setelah demo:** moderasi peer — 2 tanya + 1 apresiasi.
- **Whisper coaching** (jika panik): "Masalah user — napas — IPO — demo — iterasi."

### Larangan menit terakhir

```text
"Sini laptopnya bu, pak/bu betulkan dulu biar demo lancar"
→ Tolak — merusak bukti REA/ITR; demo apa adanya + jelaskan blocker (OBS)
```

### Script coaching reasoning & transfer

```text
"Menit iterasi & transfer sama pentingnya dengan demo fitur."
"Before/after — tunjukkan bukti peer review P16, bukan hanya kata-kata."
"Transfer: pola state+render dipakai di PRJ S4/API bagaimana?"
"Jika demo error — gejala + hipotesis. Itu OBS — bukan malu."
```

## 4. Materi Inti

### Rubrik presentasi (0–5 menit — briefing siswa)

Jelaskan ke siswa — **bukan** angka skor:

- Dinilai: clarity masalah, demo DoD, **reasoning** IPO/state, iterasi peer, transfer, respons Q&A
- Rubrik lengkap guru: [09_Rubrik_Project](../../../09-rubrik/09_Rubrik_Project.md)
- Gate DoD: acceptance wajib ✅ sebelum skor penuh

### Showcase bergiliran (0–55 menit)

**Checklist presenter** (coaching):

- [ ] Masalah + user — tanpa baca slide penuh
- [ ] IPO + blueprint 30–60 detik
- [ ] Demo **DoD live** — happy path + 1 edge jika sempat
- [ ] Before/after 1 revisi (P15/P16) — screenshot/commit
- [ ] Transfer 2–3 kalimat — pola untuk S4/industri sekolah
- [ ] Backup screenshot jika live gagal

Adjust: ±8–10 presenter @ 4–5 menit — overflow → jadwalkan lanjut atau station gallery.

### Peer Q&A (55–70 menit)

Per presentasi (atau batch):

- **2 pertanyaan bernalar** — mengapa desain, edge case, layer
- **1 apresiasi spesifik** — proses/reasoning, bukan "bagus"

Contoh pertanyaan **app S3**:

| PRJ | Pertanyaan bernalar |
|-----|---------------------|
| PRJ-01 | "Mengapa status absensi di state object bukan DOM attribute?" |
| PRJ-02 | "Validasi pinjam — layer handler vs state?" |
| PRJ-03 | "Filter katalog — state global vs parameter render?" |
| PRJ-04 | "Skor kuis — dihitung di handler atau render? Mengapa?" |

**Universal:**

- "Satu bug hunt P17 — bagaimana kamu debug project sendiri?"
- "Peer review P16 — saran mana yang paling mengubah kode?"
- "AI dipakai? Bagian mana + klarifikasi per modul?"

### Jurnal refleksi (70–85 menit)

Prompt individual (kertas/digital):

```text
Dari Kelas X ke XI Semester 3 — 3 perubahan cara berpikir:
1. …
2. …
3. …

Satu capability paling tumbuh (OBS/REA/COM/ITR/TRF/TEC):
Satu target Semester 4:
```

Guru keliling — clarifying questions: "Contoh konkret dari PRJ kamu?"

### Closing — preview S4 (85–90 menit)

- API, persistensi, kolaborasi tim
- Simpan link artefak S3 untuk portofolio S4 P18
- Apresiasi effort semester — bukan ranking

## 5. Alur Live Coding / Live Modeling

### Persiapan

- Urutan presenter + timer.
- Rubrik project — guru only.
- Kamera/foto izin — arsip MA; wali/OSIS jika undangan.
- **Tidak** sesi last-minute coding.
- Pool pertanyaan Q&A di papan.

### Skrip showcase

```text
[0–5] Briefing: reasoning + iterasi + transfer; no ranking
[0–55] Showcase 4–5 menit × N (adjust timeline)
       Guru: timekeeper, moderasi, coaching whisper
[55–70] Peer: 2 tanya + 1 apresiasi per presentasi
[70–85] Jurnal refleksi — 3 perubahan cara berpikir
[85–90] Closing + preview S4 + kumpul artefak
```

### Jika demo gagal live

1. Presenter sebut gejala (OBS)
2. Tunjuk before/after revisi + screenshot backup
3. Guru normalisasi — honesty = COM/ITR
4. Lanjut Q&A reasoning — desain tetap dinilai

### Modeling pertanyaan Q&A (papan)

```text
✓ "Mengapa render full replace vs incremental DOM?"
✓ "Circular import — bagaimana struktur modul final kamu?"
✗ "Kok UI-nya norak?" (redirect ke clarity & user need)
```

**Dilarang:** guru mengetik fix di proyektor saat showcase.

---

## 6. Latihan Membaca Kode

Showcase **bukan** walkthrough kode baris-per-baris. Gunakan snippet untuk **latihan Q&A reasoning** (opsional 5 menit sebelum demo pertama):

```javascript
// Presenter claim: "State immutable"
function updateItem(id, patch) {
  state.items = state.items.map(it =>
    it.id === id ? { ...it, ...patch } : it
  );
  render(state);
}
```

| Pertanyaan coaching (Q&A) | Kunci |
|---------------------------|-------|
| Benarkah immutable? | Spread item — array baru, object patch — cukup untuk demo |
| Alternatif? | Structured clone, immer-style — diskusi REA |
| Tanya peer bernalar? | "Mengapa map bukan find+mutate?" |

```javascript
// Before/after iterasi — untuk latihan presentasi
// BEFORE: addEventListener di dalam render()
// AFTER: delegation di main.js
```

| Pertanyaan membaca | Kunci |
|--------------------|-------|
| Iterasi P16/P17 link? | Listener bug hunt → fix delegation |
| Narasi before/after? | Gejala → hipotesis → fix → regresi |

---

## 7. Praktik Mandiri Siswa

1. **Presentasi 4–5 menit** — DoD + IPO + demo + iterasi + transfer.
2. **Peer Q&A** — 2 pertanyaan + 1 apresiasi ke presenter lain.
3. **Tunjuk bukti revisi** — before/after peer review.
4. **Jurnal refleksi** — 3 perubahan cara berpikir X→XI S3.
5. **Kumpulkan artefak** — link/folder untuk portofolio S4.
6. **Target S4** — 1 kalimat.

---

## 8. Kesalahan Umum

| Siswa | Guru |
|-------|------|
| Presentasi = baca kode semua file | Coaching: IPO + demo + iterasi |
| Skip before/after iterasi | Wajibkan bukti P16 |
| Refleksi generic ("jadi lebih pintar") | Tanya: contoh P13/P16/P17 |
| Peer roast desain | Moderasi — redirect ke reasoning & DoD |
| Guru over-praise hanya UI cantik | Puji reasoning & iterasi semua |
| Ranking kelas / juara | Explicit: tidak ada juara |
| Menit terakhir minta guru fix | Tolak — demo apa adanya |
| Lupa transfer ke S4 | Prompt: "Pola state+render di API nanti?" |
| Guru tulis refleksi siswa | Individual — authentic voice |
