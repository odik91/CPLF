## Learning Transformation

Dari semester yang “sudah dilalui” → semester yang **bisa disebut milik sendiri**: apa yang tumbuh, apa yang diarsip, apa yang dibawa ke S2 — bukan menghapus jejak, bukan memulai Blok S2 hari ini.

## Capaian pembelajaran (Taksonomi Bloom revisi)

| Kode | Level | Siswa mampu … |
|---|---|---|
| **C1** | Mengingat | Menyebut 4 blok S1, 4 outcome, arti arsip dan transfer |
| **C2** | Memahami | Menjelaskan beda P34 vs P33 (jurnal vs panggung) vs S2 P01 (belum mulai) |
| **C3** | Menerapkan | Mengisi jurnal + checklist arsip folder project S1 |
| **C4** | Menganalisis | Memetakan 1 jejak S1 ke kebutuhan S2 (halaman hidup / DOM) |
| **C5** | Mengevaluasi | Memilih 3 kemampuan yang benar-benar tumbuh + 1 target S2 yang jujur |
| **C6** | Mencipta | Paket penutup: jurnal + daftar arsip (siap dibuka lagi di S2) |

**Fokus:** C3–C5 · **Puncak:** C5–C6 · S2 (DOM / halaman hidup) **belum** dibangun hari ini

## Bukan project baru

Folder skill hanya **lembar jurnal + checklist arsip**. Yang diarsip adalah **project S1 yang sama** (P23–P33). Tidak ada HTML/CSS/JS fitur baru.

Lembar: [skill-js/p34-refleksi/](../../../materi-ajar/base-4jp/kelas-x/semester-1/skill-js/p34-refleksi/)

## Peta S1 (4 blok)

| Blok | P | Inti yang dibawa |
|---|---|---|
| 1 Orientasi | 01–05 | Masalah sebelum solusi · spek · AC · klarifikasi |
| 2 Static | 06–12 | Semantik HTML · CSS keterbacaan · section · form sebagai data |
| 3 JS vanilla | 13–22 | Nilai, variabel, kondisi, array/object, debug, DOM klik pertama |
| 4 Project | 23–33 | Spek → bangun lapis → uji → peer → revisi → polish → DoD → showcase |

## Outcome S1 (centang jujur)

1. Membingkai masalah & menulis requirement sederhana
2. Membangun halaman statis (HTML + CSS) yang terbaca
3. Memakai JS dasar pada halaman (bukan hanya generate/copy)
4. Menjelaskan alasan solusi

## Preview S2 (jendela, bukan pelajaran)

Di jalur 4JP, HTML/CSS dasar **sudah** di S1. S2 direncanakan sebagai **halaman hidup**: event lebih dari dua klik spek S1, update DOM terkendali, form+validasi di UI, list dinamis, state sederhana.

Hari ini cukup: **satu kalimat target** (“di S2 saya ingin … karena di S1 saya masih …”). Bukan `addEventListener` bab baru.

## Konsep inti

| Istilah | Arti hari ini |
|---|---|
| **Refleksi** | Menulis apa yang tumbuh, dengan bukti dari artefak |
| **Arsip** | Folder project + spek + kartu status + kartu presentasi tetap utuh |
| **Transfer** | Pola S1 (spek, AC, lapisan, regresi) dipakai lagi di S2 |
| **Preview S2** | Arah: halaman hidup / DOM — bukan bab baru hari ini |
| **Target S2** | Satu kalimat jujur, bukan daftar 10 fitur |

## Cognitive Trap

- Menghapus `log-revisi` dan gap “biar portofolio bersih.”
- Membuka tutorial DOM 40 menit “sekalian libur.”
- Jurnal: “saya belajar banyak” tanpa bukti file.
- Menilai diri hanya dari palet vs teman.
- Menganggap S2 akan mengulang HTML dari nol (di 4JP: tidak).

## Guiding Questions

1. Tiga kemampuan: masing-masing punya bukti file/perilaku, atau hanya rasa?
2. Folder project: spek, AC, kartu status, kartu presentasi masih ada?
3. Yang kutransfer ke S2: spek/AC/regresi — atau hanya “mau bikin lebih ramai”?
4. Target S2: satu celah S1, atau daftar impian?
5. Hari ini: saya menutup S1 atau diam-diam membuka S2?

## Kriteria penerimaan

- [ ] Jurnal: 3 kemampuan + bukti + 1 kesalahan/perbaikan + 1 target S2
- [ ] Checklist arsip terisi (file ada / tidak ada — jujur)
- [ ] Satu kalimat transfer (pola S1 → S2)
- [ ] Tanpa fitur baru / tanpa hapus jejak / tanpa bab DOM penuh
- [ ] Folder skill tidak menimpa project

## Formatif

## Catatan Guru

Rayakan proses. Jangan ranking. Preview S2 pendek. Nilai jurnal yang punya bukti file, bukan yang paling puitis.
